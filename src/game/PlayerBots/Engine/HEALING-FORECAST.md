# Priest healing forecast boundary

## Purpose

F54c extends the snapshot-only Priest triage input with conservative estimates of healing that is already in flight or already attached to a party member. It is not a castability decision, does not change Core's heal resolution, and does not close the action's threat estimate.

All data stored in `PartySnapshot` is scalar/GUID-only. No `Player`, `Unit`, `Spell` or `Aura` pointer is retained after `PartySnapshotBuilder::Build`.

## Credited sources

1. **In-flight direct heal.** A source member contributes only when its current Core Spell is in PREPARING or CASTING state, is not channeled, and contains exactly one effect: `SPELL_EFFECT_HEAL`. The effect must use exactly one explicit single-unit selector (`TARGET_UNIT_CASTER`, `TARGET_UNIT_FRIEND` or `TARGET_UNIT`), target a same-Group Player on this map/instance, and have no SpellScript (`ScriptId == 0`). The amount is calculated by Core's `Spell::CalculateDamage` against that target and rounded downward for the forecast. Mixed effects, area/party/chain targeting, scripts and unresolved targets are not credited.
2. **HoT.** Non-scripted `SPELL_AURA_PERIODIC_HEAL` auras contribute the Core-stored caster-adjusted tick amount after Core's target-side `SpellHealingBonusTaken`. Core then calls `rand_ditheru` on every tick, so the value-only forecast stores the reachable `floor(amount)` / `ceil(amount)` interval. The aggregate `periodicHealRemainingAmount` credits only the guaranteed floor multiplied by finite remaining ticks; the timeline carries both lower and upper values per tick. A positive sub-one amount therefore has a valid [0, 1] interval and is not promoted to guaranteed healing. Auras with scripts, no caster, invalid/nonpositive amounts, expired duration or unknown tick cadence are omitted.
3. **All-school absorb for triage.** `SPELL_AURA_SCHOOL_ABSORB` auras still contribute to the coarse `allSchoolAbsorbRemainingAmount` only when `m_miscvalue == 0x7f`, the complete seven-school mask, the Aura has no `AuraScript`, and the Aura has no charges. Configured `SpellScript` auras remain excluded except for the exact Vanilla Power Word: Shield ranks registered by `spell_priest_power_word_shield` (17, 592, 600, 3747, 6065, 6066, 10898, 10899, 10900, 10901 and 27607). That audited `OnHit` callback only applies Weakened Soul after a successful shield hit; it does not mutate the absorb Aura or its amount. The live Core fixture confirmed Spell 17's `ScriptId=669`, no AuraScript, all-school mask 127 and remaining absorb 48. Other scripted/charged absorbs remain excluded. School-specific shields are not credited to this coarse triage total.

F54l separately copies bounded value-only `SchoolAbsorbForecastSnapshot` rows for School Absorb Auras whose mask is in 1..127, amount is finite/integer/Core-int32-representable, duration is still active, Aura has no charges or AuraScript, and script path is either unscripted or the audited Power Word: Shield allowlist. Core checks `(auraMask & damageSchoolMask) != 0` and consumes those pools after resistance; a charged Aura can drop its final charge and zero the remaining amount, so it is excluded. The time projection accepts only known-school damage amounts already measured immediately before the school-absorb stage; it does not invent random resistance outcomes. Truncated absorb lists receive no partial credit, unknown-school damage is rejected when an active shield could match, and same-time damage with different shield-match sets is rejected. `SPELL_AURA_MANA_SHIELD` remains excluded because its absorb consumes a separate, changing mana resource.

## Reservation and de-duplication

F54b Heal reservations remain the authority for Engine-owned direct casts. The snapshot builder deliberately leaves `currentSpellHealingAmount` at zero for an Engine-owned cast. Triage credits the other-Bot reservation from the shared `PartyCoordinator`, so the same in-flight cast is not counted twice. Non-Engine player casts are credited from the caster member's `currentSpellTargetGuid` and `currentSpellHealingAmount`.

The direct-cast, HoT and all-school absorb amounts are added to the shared reservation amount using 64-bit intermediate arithmetic. The result is capped at the target's current raw health deficit before projected health is ranked. This prevents integer wrap and prevents the forecast from assigning more than full health.

## Shared uncovered-deficit accounting

F54c uses one pure helper, `GetPriestUncoveredMissingHealth`, for both target triage and the direct-heal action adapter. It subtracts supported non-Engine direct casts, ordinary remaining HoT ticks, universal absorbs and other Bots' Heal reservations from the current deficit, with 64-bit accumulation and a deficit cap. `PriestDirectHealAction::IsUseful` and `ExecuteCore` use that same result before deciding whether a cast is useful and how much to reserve. This prevents the selector and action adapter from disagreeing or reserving healing already covered by known incoming effects.

### F54k — Core random-dither bounds for periodic healing (trusted-runtime validated)

Core's `Aura::PeriodicTick` calculates the target-adjusted periodic-heal amount and calls `rand_ditheru` for every tick. The random draw is independent of the detached snapshot and resolves to either the floor or ceiling of the positive input, selected according to its fractional part. A single expected/integer amount would falsely imply an exact future tick.

The snapshot stores `healingPerTick` as the conservative floor and `healingPerTickUpperBound` as the possible ceiling. The aggregate consumed by Priest triage continues to use only the floor, so uncertain extra healing is never treated as guaranteed. `HealingTimelineEvent` carries both amounts; `ProjectHealingTimeline` returns the lower-bound result plus maximum final health/effective-healing/overheal fields. Exact direct heals and damage events retain equal lower/upper amounts. Positive sub-one periodic heals may legitimately have a zero lower bound and a one-point upper bound.
